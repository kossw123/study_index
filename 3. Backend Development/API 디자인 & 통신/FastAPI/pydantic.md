## 왜 필요한가?

- 타입 힌트와 기본값을 통해 자동으로 데이터를 검증 및 에러 응답을 출력한다.
- 자동으로 데이터를 변환해준다.
- swagger ui 문서화를 자동으로 해준다.

## 정의

데이터가 내가 원하는 형태가 맞는지 검사하고, 원하는 형태로 강제 변환해주는 라이브러리다.

## 동작 과정

Pydantic은 BaseModel을 상속받은 객체를 통해 원하는 데이터 틀을 만든다.

그리고 FastAPI Router에 꽂아주면, FastAPI가 들어오는 데이터를 이 틀에 합격했는지 알아서 검사한다.

```
from pydantic import BaseModel

class LoginRequest(BaseModel):
	username: str | None = None  // 타입 힌트와 기본값을 통한 데이터 검증
	password: str
```

그리고 웬만하면 데이터를 규격에 맞게 알아서 캐스팅해준다.

e.g) 숫자가 아닌 문자열 25를 받은 경우 캐스팅될 수 있다면 캐스팅을 해준다.


## pydantic의 성능 저하 문제에 대한 고찰

pydantic이 성능을 잡아먹는건 대부분 캐스팅 때문이다.
그러나 그 중에 파이썬의 언어 구조적 한계와 데이터를 변화시키는 과정이 범인이다.

1. 가장 큰 성능 저하는 데이터를 검증 한 후, 이를 파이썬 딕셔너리나 클래스로 새로 만들고 복사하는 과정에서 일어난다.
	- 즉, 조건부 deep copy를 한다.
2. 또한 커스텀 검증기가 복잡한 조건을 가진다면 성능이 “뚝” 떨어진다.
3. 무분별하게 내부 함수, 비즈니스 로직 연산, DB 데이터를 다룰 때도 계속 pydantic 모델로 변환하고 변환하는 과정이 성능을 저하시킨다.

## 대체품 등장

pydantic v2와 rust란게 등장했는데, v2는 버전 업그레이드고, rust는 초고속 언어로 구성하면 성능 향상이 된다.

e.g)

- FastAPI에서 JSON을 처리할 때는 model_validate(json.loads(data)) 대신에 rust 엔진을바로 타는 다음과 같은 라이브러리나 함수를 사용한다.
- model_validate_json(data)

## 프로젝트에서는 어디에서 사용하는가?

- 요청에 대한 모델을 구현할 때 사용된다.
