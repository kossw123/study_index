

## 왜 필요한가?  

- 레거시 시스템이 Servlet를 사용한다면 복잡함을 줄일 수 있는 가장 효율적인 수단이다.
- JSP는 MVC 패턴과 연계하여, 유지보수를 용이하게 한다.
  
## 정의  

JSP는 HTML문서 내부에 Java코드를 삽입할 수 있는 서버 스크립트 언어다.
즉, HTML 문서에 서버 코드를 삽입할 수 있다.

이는 동적 웹 프로그래밍을 더 쉽고 편리하게 관리하기 위해 탄생했다.
정확히는 기존의 서블릿(Servlet)의 치명적인 단점을 해결하기 위해 탄생했다.

Servlet은 Java코드 안에 HTML을 넣는 방식이다.
그러나 화면을 수정하면 재컴파일이 빈번하고 오타를 찾기도 너무 힘들었다.

이를 해결하기 위해 JSP는 다음과 같은 이념을 내세운다.
	"HTML을 중심으로 짜자“
HTML 코드에 Java를 넣는 방식을 통해 화면을 구현하는데, 편리해지고, 디자이너와의 역할 분담이 쉬워졌다.
왜냐하면 디자이너는 HTML만 만지고, 개발자는 Java코드만 만지면 되니까

## 동작 과정  

- **JSP 페이지 요청:** 
	- 클라이언트(웹 브라우저)가 URL을 통해 특정 JSP 페이지를 웹 서버에 요청합니다.
- **컨테이너 전달 및 파일 확인:** 
	- 웹 서버가 요청을 받아 서블릿 컨테이너(예: Tomcat)로 전달합니다. 
	- 컨테이너는 해당 JSP 파일이 처음 요청되었는지 또는 기존에 비해 수정되었는지를 확인합니다. 
- **자바 소스로 변환 (Translate):** 
	- 요청된 JSP 파일이 처음이거나 수정되었을 경우, 컨테이너 내의 JSP 엔진(Jasper)이 JSP 파일을 서블릿 자바 소스(`.java`) 파일로 변환합니다. 
- **컴파일 (Compile):** 
	- 변환된 `.java` 파일을 서블릿 클래스(`.class`) 파일로 컴파일합니다. 
		- (JSP가 수정되지 않았다면 이 과정은 생략되고 기존에 컴파일된 클래스를 재사용합니다.) 
- **메모리 적재 및 실행:** 
	- 컴파일된 서블릿 클래스가 메모리(WAS)에 적재되고, 클라이언트의 요청에 대한 응답을 처리합니다. 
- **결과 응답:** 
	- 서블릿이 처리한 결과를 웹 서버에 전달하고, 웹 서버는 브라우저가 인식할 수 있는 HTML 문서 형태로 변환하여 클라이언트에게 최종 전송합니다.
