## 왜 필요할까?

- **실시간성 및 개인화 요구 대응:** 모든 사용자에게 동일한 고정 화면만 보여주던 정적 웹의 한계를 극복하고, 사용자의 입력, 로그인 상태, 실시간 데이터 변화 등 컨텍스트에 따른 맞춤형 정보와 인터페이스를 실시간으로 연산하여 제공하기 위해 탄생했다.

## 정의

- **동적 웹 프로그래밍 (Dynamic Web Programming)**은 클라이언트의 요청이 들어온 그 시점에, 서버가 비즈니스 로직을 구동하거나 데이터를 가공하여 **요청별로 각기 다른 웹 페이지(HTML)나 데이터(JSON)를 실시간으로 생성하여 제공하는 개발 패러다임**이다.
- 반드시 데이터베이스(DB) 연동이나 거대한 WAS 장비가 구축되어야만 성립하는 것은 아니며, 서버의 현재 시간을 계산하여 보여주거나 단순 메모리 연산을 처리하는 것 역시 동적 웹 프로그래밍의 범주에 속한다.

## 아키텍처의 진화와 올바른 기술적 이해

### 💡 "서버(Server)는 기계(Hardware)가 아닌 프로그램(Software)이다"
- 하나의 물리적인 컴퓨터 안에서 웹 서버 프로그램(Nginx 등)과 웹 애플리케이션 서버(WAS) 프로그램을 동시에 띄워 자원을 나눠 쓸 수 있다. 시스템의 물리적 대수와 소프트웨어 구조는 별개의 영역이다.

### ⚠️ FastAPI, Spring Boot의 본질: 내장 서버(Embedded Server) 아키텍처
현대 백엔드 생태계에서 FastAPI나 Spring Boot가 단독으로 서비스를 구동할 수 있는 원리는 "웹 서버와 WAS를 하나로 합친 기계나 새로운 프로그램"이기 때문이 아니다.

- **프레임워크(Framework):** 비즈니스 규칙과 URL 라우팅, 데이터 검증 로직을 구현하는 소프트웨어 소스코드 템플릿이다.
- **내장 서버 엔진의 탑재:** 과거에는 개발자가 Apache Tomcat이나 외부 ASGI 실행기를 서버에 별도로 설치하고 코드를 빌드하여 수동으로 꽂아 넣어야 했다. 현대 프레임워크들은 이 번거로움을 해결하기 위해 **어플리케이션 빌드 아티팩트 내부에 웹 서버 엔진(Spring Boot는 Tomcat, FastAPI는 Uvicorn 등)을 내장(Embedded)** 시켰다.
- **존재 이유:** 하드웨어 발달 때문이 아니라, **"개발자가 인프라 세팅에 들이는 공수를 최소화하고, 단일 실행 파일 하나만으로 어디서나 즉시 서비스를 구동할 수 있도록 배포 생산성을 극대화하기 위함"**이다.

## 현대 엔터프라이즈의 3-Tier 아키텍처 배치 전략

프레임워크가 내장 서버를 가지고 있어 단독 구동이 가능함에도 불구하고, 대규모 프로덕션 환경에서는 여전히 앞단에 전문 웹 서버를 전면 배치하는 분산 구조를 고수한다.

```
[Client] ──(HTTP/HTTPS)──> [Web Server (Nginx / Apache)]  
│  
│ Reverse Proxy / 로드밸런싱 / SSL 종단  
▼  
[Embedded WAS (FastAPI + Uvicorn)]  
│  
│ SQL / ORM  
▼  
[Database (MySQL)]
```

1. **인프라 제어의 전문화:** 
	- 전면의 **웹 서버(Nginx, Apache 등)**는 대규모 동시 커넥션 대기, 로드밸런싱, SSL/TLS 인증서 암복호화, DDoS 방어 등 네트워크 및 관문 보안 제어에 집중한다. 
2. **비즈니스 연산의 집중화:** 
	- 뒷단의 **WAS(내장 엔진 + 프레임워크 애플리케이션)**는 웹 서버가 최적화하여 넘겨준 안전한 요청만 수신하여, 오직 핵심 도메인 로직 연산과 데이터 가공 처리에만 CPU 자원을 전담하여 사용한다. 
## 프로젝트에서는 어디에서 사용하는가? 
- **전체 패러다임 채택:** 
	- 우리 프로젝트는 고성능 비동기 동적 웹 프로그래밍을 구현하기 위해 **FastAPI 프레임워크**를 전면 채택하였다. 
- **구동 구조:** 
	- 개발 단계인 현재는 FastAPI 내부에 통합된 고성능 ASGI 내장 서버인 **Uvicorn** 런타임을 구동하여 실시간 데이터 요청 및 응답 처리를 수행하고 있다. 향후 배포 단계에서는 최적의 보안과 분산 제어를 위해 전면에 Nginx 웹 서버를 결합하는 표준 3-Tier 아키텍처로 확장할 계획이다.
