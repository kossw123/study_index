## 왜 필요할까?

- **인간의 선형적 사고 모델 부합:** 인간의 뇌는 코드를 위에서 아래로, 시간의 순서대로(직렬적으로) 읽을 때 가장 명확하게 이해한다. 비동기 코드가 동기식 구조처럼 평평하게 읽혀야만 개발자의 인지 부하를 줄이고 로직의 허점을 쉽게 파악할 수 있다.
- **제어 흐름 및 예외 처리의 통합:** 비동기 작업의 파편화된 스코프와 복잡한 에러 처리 경로를 기존 언어가 가졌던 표준 제어문(`if`, `for`, `try...catch`) 안으로 완벽히 통합하기 위함이다.

## 동기식 가독성이 필요한 진짜 이유 분석

### 1. 콜백 변수의 스코프(Scope) 제약 해소와 올바른 범위
- **과거의 한계:** 비동기 함수의 결과값을 활용하려면 반드시 `.then((data) => { ... })`이라는 콜백 함수 블록(방) 안으로 진입해야만 했다. 이 방을 벗어나는 순간 컴퓨터는 해당 변수를 망각하므로, 연쇄적인 비동기 작업 시 방 안에 방이 계속 생성되는 중첩 무덤이 발생했다.
- **`async/await` 구조의 개선:** `await` 키워드를 사용하면 비동기 결과값을 마치 일반 지역 변수에 대입하듯 선언할 수 있다. 우측으로 꺾여 들어가는 들여쓰기가 사라지므로, **해당 함수 블록(`async def` / `async function`) 내부의 하단 흐름 어디서든** 변수를 자유롭게 공유하고 재사용할 수 있게 된다. (※ 단, 언어 고유의 함수/블록 스코프 제약은 여전히 철저히 준수되므로 함수 외부에서는 접근할 수 없다.)

### 2. 가독성 비교 및 에러 처리 구조의 혁신

#### ❌ 올바르지 못한 프라미스 중첩과 에러 분산 구조
과거 방식도 리턴 체이닝을 쓰면 들여쓰기를 펼칠 수는 있었으나, 비동기 단계별로 각기 다른 독립적 에러 대응(성공 로직과 실패 로직의 역순 배치)을 구현하려면 코드가 기형적으로 변했다.

```javascript
// 각 비동기 단계마다 .catch가 역순으로 꼬리를 물어 디버깅이 어려워짐
login()
  .then(user => {
    return getProfile(user.id);
  })
  .then(profile => {
    return getPost(profile.lastPostId);
  })
  .then(post => { /* 성공 처리 */ })
  .catch(err => { 
    // ❓ 체이닝 끝에 둔 에러 처리는 정확히 어느 단계(로그인? 프로필? 글조회?)에서 터진 것인지 한눈에 인지하기 어렵다.
    console.error("비동기 흐름 중 어딘가에서 에러 발생:", err); 
  });
```

#### ✨ `async/await`와 `try...catch` 기반의 동기식 통합 제어 구조
순수 동기식 코드를 작성할 때와 완전히 동일한 문법 아키텍처를 사용하여, 비즈니스 성공 흐름과 예외 상황 처리 흐름을 논리적으로 완벽히 격리할 수 있다.

```javascript
async function 로직_프로세스_실행() {
  // 1. 성공 시의 비즈니스 시퀀스가 위에서 아래로 맑게 읽힘
  try {
    const user = await login();       # 스코프 내 변수 선언
    const profile = await getProfile(user.id);
    const post = await getPost(profile.lastPostId);
    return { status: "SUCCESS", data: post };
    
  } catch (error) {
    // 2. ⚠️ [주의] 에러 처리가 편해졌다고 해서 '오류 처리 설계'가 생략되어선 안 된다.
    // 런타임 크래시를 방지하기 위해 예외 복구(Fallback) 및 로깅 전략을 반드시 명시해야 한다.
    log_critical_error("비동기 처리 시퀀스 실패", error);
    return handle_error_fallback(error);
  }
}
```

## 프로젝트에서는 어디에서 사용하는가?

- **프론트엔드 API 오케스트레이션:** React 컴포넌트 내부에서 비동기 HTTP 요청(Axios)들을 연달아 호출할 때 사용한다. 예를 들어, `사용자 인증 데이터 요청` ➔ `해당 사용자 권한 파싱` ➔ `권한 기반 UI 렌더링` 구조를 가독성 높은 직렬 파이프라인으로 구성하는 데 전면 활용하고 있다.
- **백엔드 트랜잭션 에러 전파:** FastAPI 컨트롤러(Router) 및 서비스 계층에서 데이터베이스 비동기 세션을 다룰 때, 쿼리 실패 예외가 비동기 루프 뒤로 숨지 않고 동기식 `try...catch` 문맥에 정확히 걸려 들어와 글로벌 예외 핸들러(`ExceptionHTTPHandler`)로 안전하게 전파되도록 설계하는 근간이 된다.
