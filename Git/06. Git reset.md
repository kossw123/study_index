## 왜 필요한가?

- 과거의 특정 커밋 상태로 돌아가거나, 실수로 올린 코드를 취소하기가 가능하다. 
	- 실수로 추가한 파일 제외 (Unstage)
	- 잘못 작성한 커밋 취소 (Undo commit)
	- 작업 내용 완전히 폐기 (Discard Changes)
## 정의

> 현재 작업 중인 브랜치의 시점(HEAD pointer)을 특정 커밋으로 강제 이동시켜, 과거 상태로 되돌리는 명령어다.

1. HEAD 위치 이동 : 
	- 브랜치가 가리키는 최신 커밋의 위치를 과거의 특정 커밋으로 바꾼다.
2. 작업 단계 되돌리기 : 
	- Git의 3가지 공간의 상태를 원하는 과거 시점으로 동기화한다.
3. 이력 정리
	- 원격 저장소에 올리기 전, 로컬에서 잘못 만든 커밋들을 깔끔하게 지우고 새로 정리한다.

## 동작 과정

```
path (main) 
$ git reset (mode) (commit tag)
```

### mode

| 옵션      | 커밋 취소 | 파일 수정본 유지 여부       | 위험도 및 용도                             |
| ------- | :---: | ------------------ | ------------------------------------ |
| --soft  |   O   | 유지 (git add 된 상태로) | 커밋 메시지만 바꾸거나, <br>여러 커밋을 하나로 묶을 때    |
| --mixed |   O   | 유지 (git add 된 상태로) | `git add`를 취소하고 <br>파일을 다시 수정하고 싶을 때 |
| --hard  |   O   | 모두 삭제 (과거로 완벽 복구)  | 작업 내용을 전부 버리고 <br>특정 시점으로 완전히 되돌릴 때  |
