```
A -- B -- C -- D (HEAD, main)
```

다음과 같은 commit이 있을 때,

```
git reset --hard B
```

다음과 같은 명령어를 실행한다면

```
A -- B (HEAD, main)
 \
  C -- D (dangling)
```

다음과 같은 형태가 된다.

dangling이란 브랜치, 태그, HEAD 등에서 연결되지 않은 객체를 의미한다.

즉, C는 어디에서도 참조되지 않는 객체가 된다.

D는 C를 참조하니 예외.

즉, reset은 HEAD가 브랜치를 가리키는 상태일 때,

현재 브랜치가 가리키는 commit을 특정 commit으로 이동시키고, 옵션에 따라 index, working directory를 해당 commit의 상태로 맞춘다.

# -soft 옵션

```
git reset --soft HEAD~1
```

commit만 취소하고, staging과 파일은 유지한다.

즉, Repository에 있는 commit만 취소하고 Working directory, Staging area는 유지한다.

보통 commit의 메시지를 수정하거나, commit을 다시 만들 때 사용한다.

# -mixed(기본값)

```
git reset HEAD~1
```

또는

```
git reset --mixed HEAD~1
```

commit을 삭제하고, Staging area를 초기화하지만, 파일은 유지한다.

즉, Working Directory는 유지하고, Staging area, repository에 있는 commit은 삭제한다.

주로 add를 잘못했을 때 사용한다.

# -hard

```
git reset --hard HEAD~1
```

commit을 삭제하고, Staging area를 초기화하고, 파일도 삭제한다.

즉, 과거로 돌린다.

주로 완전 롤백할 때 사용한다.
