"working directory나 index 파일들을 특정 commit이나 staging 상태로 되돌린다.“

Git 2.23부터 도입되었다.

왜냐하면 checkout으로 할 수 있는 작업들이 너무 많았기 때문이다.

이제는 checkout을 통해 하던 파일의 복구와 브랜치의 이동은 다음과 같이 변경된다.

```
$ git switch // 브랜치 이동
$ git restore // 파일 복구
```

첫 번째로 수정한 파일을 되돌릴 수 있다.

```
$ git commit -m "last commit"
$ git restore file.py
```

이 명령어는 working directory를 staging 했던 상태로 되돌린다.

다음과 같은 상태가 되는 것이다.

```
index : A
working : A (수정됨)

restore 실행

index: A
working A (수정 전)
```

두 번째로 staging을 취소할 수있다.

```
$ git add .
$ git restore --staged file.py
```

add를 통해 staging area에 올려도, restore를 통해 취소할 수 있다.

세 번째로 특정 commit으로 복구할 수 있다.

```
$ git restore --source <commit> file.py
```

file.py를 특정 commit 상태로 되돌릴 수 있다.

더 정확히 이야기하자면, 특정 파일의 어떤 시점의 commit을 working directory에 복원한다는 것이다.

네 번째로 전체 파일을 되돌릴 수 있다.

```
$ git add .
$ git commit -m "last commit"
$ git restore .
```

이 명령어는 last commit을 전부 index, 즉 staging area로 되돌린다는 것이다.

# restore와 reset의 비교

reset은 commit 또는 branch를 대상으로 하는게 좋다.
restore는 파일을 대상으로 하는 게 좋다.
