”서로 갈라진(diverging) 상태를 의미한다“

보통 local history와 repository의 history가 다른 경우 발생한다.

```
로컬 main: A ─ B ─ C
           ↑ local commit

origin/main: A ─ B ─ D
             ↑ remote commit
```

local에는 C commit이 존재하고, repository에는 D commit이 존재한다.

즉, 서로 다른 history를 가지고 있다.

“문제는 이를 해결하기 위해 pull하는 것도 안된다”

git pull은 fetch + merge를 합친 명령어다.

그렇기 때문에 Git설정에 따라 merge를 허용하지 않거나, rebase를 요구할 수 있고, 이에 따른 충돌 가능성이 있어서 pull이 중단될 수있다.

보통 해결하는 방법은 3가지다.

1. merge로 새로운 merge commit을 생성하여 해결
    
2. rebase로 기존 commit의 base를 변경하여 해결
    
3. reset으로 로컬 commit을 버려서 해결

3가지 문제가 있다.

```
"Your branch and 'origin/main' have diverged,
and have 1 and 3 different commits each"
```

remote repository와 현재 브랜치의 커밋 그래프는 다음과 같다.

```
origin/main: initialization ─ delete commit ─ delete2 commit ─ delete3 commit
local main: initialization ─ complete templete
```

즉, origin/main 브랜치의 커밋이 3개가 존재하는데, 현재 브랜치에는 없다는 것이다.

그래서 remote와 local의 history가 다르니 pull해서 합치라는 것이다.

"Changes not staged for commit"

commit을 위한 변경이 staging되지 않았다는 것이다.

이는 client 내부만 staging하고 상위 폴더에 변경사항이 제대로 올라가지 못했다는 것이다.

"Untracked files"

git이 추적하지 않는 새로운 파일이 있다.

이는 server에서의 변경사항을 Git이 추적하지 못하는 상황이다.

이 세가지 문제

1. diverged
    
2. Changs not staged
    
3. Untracked files
    

를 해결해야 한다.

첫 번째로 root 폴더로 이동하여 Untracked files와 staging이 반영이 안된 파일들을 모두 commit한다.

두 번째로 remote repository의 history와 local history를 병합한다.

git pull --rebase origin main

- rebase는 commit의 base를 변경한다.
    
- 현재 브랜치에서 변경한다면 다음과 같을 것이다.
    

```
A ─ B ─ C ─ D (origin/main)
     \
      E (main)
```

E(complete templete) commit이 로컬이다.

현재 브랜치에 있는 commit의 base를 D commit으로 변경한다.

그렇다면 다음과 같은 구조가 local에서 완성된다.

```
A ─ B ─ C ─ D ─ E' (main)
```

그 후 최종적으로 다시 push를 하면 된다.
