## 왜 필요한가?

- 동일한 웹페이지에서 사용자 요청에 따라 다른 다른 데이터를 보여줄 수 있다.
- **[1. 동적 페이지 생성]**
	- 하나의 웹페이지 주소에서 사용자가 입력한 검색어에 맞는 결과를 실시간으로 보여줄 수 있다.
- **[2. 상태 유지와 공유]**
	- 정렬 방식, 필터 조건, 현재 페이지 번호가 URL에 그대로 남기 때문에, 그 주소를 복사해 다른 사람에게 공유해도 똑같은 화면을 보게 할 수 있다.
- **[3. 서버 부하 감소]**
	- 웹사이트의 디자인은 그대로 두고, 내부 데이터만 바꿔 전달할 수 있다.
- **[4. 자원 식별(정렬/필터)]**
	- 특정 자원의 정렬 방식, 노출 개수, 카테고리 필터링을 직관적으로 지정한다.
		- 정렬 방식 : `sort=latest`
		- 노출 개수 : `limit=10`
		- 카테고리 필터링 : `category=shoes`
## 정의

- URL 끝에 물음표를 붙이고, `이름=값`형태로 정보를 적어 서버로 전달하는 방식이다.
- 여러 개를 보낼 때는 `&(엠퍼샌드)` 기호로 연결한다.
- 주로 다음과 같은 용도로 서버의 데이터 조회(GET) 요청에 사용된다.
	- 검색어 전달
	- 페이지 번호 지정
	- 정렬 방식 선택

## 동작 과정

- 다음과 같이 사용한다.
```
주소?이름1=값&이름2=값2
> https://example?name=test&value=100
```

### e.g)

- 기본 주소를 다음과 같을 때

```
> 기본 주소 : https://myshop.com
```

### **[만약 쿼리 스트링이 없는 경우]**
- 쿼리 스트링이 없을 때는 다음과 같이 페이지를 만들어야 한다.

```
1. 신발 페이지 : 
> .../shoes/nike
2. 신발 중 270 사이즈 페이지 : 
> .../shoes/nike/270
3. 신발 중 270 사이즈를 가격 낮은 순으로 정렬한 페이지 : 
> .../shoes/nike/270/low-price
...
```

- 이런 식으로 조건이 늘어날 때마다 수천, 수만 개의 웹페이지 주소를 미리 다 만들어 두어야 하기에, 사실상 구현이 불가능하다.

### [쿼리 스트링이 있는 경우]

- 단 하나의 주소(`/shoe`)만 만들어 두고, 뒤에 붙는 쿼리 스트링 조건에 따라 서버가 DB에서 필요한 정보만 뽑아 화면에 보여준다.
```
https://myshop.com?shoe=nike&size=270&low-price=true
```
