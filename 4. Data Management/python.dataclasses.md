## 왜 필요할까?

- **DTO 생성을 위한 반복 코드 제거:** 
	- 파이썬에서 순수하게 데이터만을 담기 위한 객체(Data Transfer Object)를 정의하려면 `__init__`, `__repr__`, `__eq__` 같은 특수 메서드들을 항상 고정적인 형태로 구현해야 해서 무의미한 보일러플레이트 코드가 반복된다.
- **가독성 및 생산성 향상:** 
	- 클래스 내부 속성이 늘어나거나 변경될 때마다 생성자 매개변수와 내부 할당 로직을 사람이 직접 수정하다 보면 오타나 누락이 발생하기 쉬운 환경을 제공하므로, 이를 자동화하기 위해 탄생했다.

## 정의

- **`dataclasses`**는 파이썬 3.7부터 정식 도입되었으며, **클래스 선언에 작성된 타입 힌트(Type Hint) 명세를 기반으로 초기화 및 비교를 위한 특수 메서드(Magic Method)들을 런타임에 자동으로 주입해 주는 기본 라이브러리 모듈**이다.

## 장점 및 단점

### 1. 장점
- **보일러플레이트 완벽 제거:** 
	- `__init__`, `__repr__`, `__eq__` 등의 구현부가 코드가 실행될 때 백엔드에서 자동 구성된다.
- **정적 타이핑 연동 극대화:** 
	- 필드마다 타입 힌팅을 강제하므로 IDE의 자동 완성 도움을 완벽히 받을 수 있고, `mypy` 같은 정적 분석 도구와 결합하여 코드 품질을 높인다.
- **얕은 불변성(Shallow Immutability) 지원:** 
	- `@dataclass(frozen=True)` 설정을 통해 객체의 필드 값을 함부로 재할당하거나 삭제하지 못하도록 동적 락을 걸 수 있다.

### 2. 단점 및 실무 주의점
- **⚠️ 자동 유효성 검증(Validation) 부재:** 
	- 데이터 클래스는 입력된 값이 진짜 선언된 타입과 일치하는지, 비즈니스 규칙에 유효한지 검사하는 **데이터 검증을 기본적으로 전혀 수행하지 않는다.** 타입 매칭 강제 및 파싱 기능까지 완벽히 레버리지하고 싶다면 **`Pydantic`** 모델을 채택해야 한다.
- **`frozen=True` 객체의 내부 가변성 한계:** 
	- 객체의 주소 및 속성 재할당은 차단하지만, **필드 내부에 들어있는 리스트(`list`)나 딕셔너리(`dict`) 같은 가변 객체 내부의 요소를 수정하는 행위(`append`, `pop` 등)는 원천적으로 막지 못한다.**
- **상속 규칙의 까다로움:** 
	- 부모 클래스와 자식 클래스가 모두 데이터 클래스일 경우, 파이썬 문법 특성상 "기본값이 없는 필드"가 "기본값이 있는 필드"보다 반드시 먼저 선언되어야 하므로 상속 구조 설계 시 배치 순서 제약이 엄격하다.

## 동작 과정

데이터 클래스는 컴파일 타임이 아닌, **파이썬 인터프리터가 모듈 코드를 읽고 클래스 정의를 실행하는 런타임(Runtime/로드 타임)**에 동작한다.

1. **클래스 필드 검사:** 
	- 데코레이터가 클래스 내부에 선언된 변수 중 타입 힌트가 붙은 순수 데이터 필드들을 차례로 탐색한다.
2. **소스코드 동적 문자열 생성:** 
	- 수집된 필드 정보를 바탕으로 필요한 `__init__`, `__repr__` 등의 내부 파이썬 소스코드를 메모리 상에서 문자열 템플릿 형태로 동적 생성한다.
3. **메서드 컴파일 및 기존 클래스 주입:** 
	- 동적으로 빌드된 문자열 코드를 파이썬 내부 컴파일러(`exec`)를 통해 실행 가능한 바이트코드로 변환한 뒤, **기존 클래스 객체의 네임스페이스 내부에 직접 주입(Mutate)한다.** 
	- (※ 완전히 새로운 클래스를 복사해 만드는 것은 기본 동작이 아니며, `slots=True` 같은 하드웨어 메모리 최적화 옵션을 활성화할 때만 특수하게 새 클래스가 생성된다.)
4. **최종 가공된 클래스 반환:** 
	- 특수 메서드가 안전하게 확장된 기존 클래스 참조본을 최종 반환한다.

## 실전 활용 패러다임

```python
from dataclasses import dataclass, field

@dataclass
class UserDto:
    username: str
    age: int
    # 💡 1. 가변 객체(List)를 안전한 기본값으로 선언하기 위한 factory 설정
    items: list[str] = field(default_factory=list)

    # 2. 초기화 완료 직후 비즈니스 제약이나 커스텀 유효성 검사를 수행하는 내장 관문
    def __post_init__(self):
        # 기술적 타입은 Pydantic처럼 강제하지 못하므로 직접 수동 검증부 구현 필요
        if self.age < 0:
            raise ValueError("나이는 음수일 수 없습니다.")
```

## 프로젝트에서는 어디에서 사용하는가?

- **내부 도메인 엔티티 및 값 객체(VO):** 외부 세계와 직접 통신하며 가혹한 검증을 타야 하는 입출력 관문(DTO)에는 **Pydantic**을 전면 배치하고, 우리 시스템 핵심 내부 비즈니스 레이어 안에서 순수하게 행위와 일관성 경계를 유지하는 불변 데이터 그릇(Value Object)을 설계할 때 **`dataclasses`**를 믹스인하여 아키텍처의 균형을 맞추고 있다.
