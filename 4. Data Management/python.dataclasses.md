## 왜 필요한가?

- **[데이터 검증을 위한 보일러플레이트 발생]**
	- python에서 순수하게 데이터만을 담기 위한 객체를 위해 repr, eq같은 함수가 필요한데, 항상 똑같은 방식으로 제작되기에 보일러 플레이트가 발생한다.
	- 속성이 늘어날 때마다 똑같은 로직을 오타 없이 작성하기에는 불필요함.

## 정의

> 타입 힌트를 기반으로 OOP에 필요한 특수 함수를 자동으로 생성해주는 모듈

## 사용방법

- '@dataclass' 데코레이터를 붙이면 된다.

## 장단점

### 장점
1. 보일러 플레이트 코드 제거
2. 유용한 기본 메서드 제공
	- 기본적으로 `__repr__` 와 `__eq__` 가 자동으로 생성된다.
3. 정적 타이핑 지원
	- 타입 힌트를 강제하므로 IDE의 자동완성이나 `mypy`와 같은 정적 분석 도구의 도움을 받기 좋다.
4. 불변 객체 지원
	- `@dataclass(frozen=True)` 라고 설정하면 수정할 수 없는 불변 객체로 만들 수 있다.

### 단점
1. 런타임 타입 검사 부재
	- 실행중에 타입 힌트와 다른 값이 입력되어도 에러가 발생하지 않는다.
	- 타입 강제가 필요하다면 `pydantic`을 사용하자.
2. 상속 구조의 복잡성
	- 부모, 자식 클래스 모두 `@dataclass`인 경우 기본값이 있는 필드의 선언 순서 규칙 때문에 상속 처리가 까다롭다.
3. 하위 버전 호환성
	- python 3.6이하에서는 기본 라이브러리로 사용할 수 없다.

## 동작 과정
### 1. 클래스 검사
- 데코레이터가 클래스 내부의 타입 힌트가 붙은 필드를 탐색한다.
### 2. 코드 동적 생성
- 칮아낸 정보를 바탕으로 `__init__`, `__repr__`, `__eq__` 등의 소스 코드를 문자열 형태로 동적 생성한다.
### 3. 컴파일 및 주입
- 생성된 소스 코드를 컴파일 타임에서 바이트코드로 변환하여 이를 대상 클래스 내부로 주입한다.
### 4. 클래스 반환
- 특수 함수들이 세팅된 새로운 클래스를 반환한다.

## 활용 방안
- 유효성 검사 및 초기화를 도와주는 `__post_init__` 메서드 활용법
- 타입 강제 및 환경변수 파싱까지 해주는 외부 라이브러리 Pydantic과의 차이점 비교
- 리스트 같은 가변 객체를 기본값으로 설정할 때 쓰는 `field(default_factory=...)` 사용법
