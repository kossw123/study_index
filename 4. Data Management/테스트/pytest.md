## 왜 필요한가?

- **[최소한의 보일러플레이트]**
	- 복잡하게 만들 필요 없이, python 고유의 `assert`문 하나만으로 모든 검증이 가능하다.
- **[압도적인 가독성]**
	- 테스트 코드가 직관적이여서, 유지보수가 쉽다.
- **[실패 로그의 친절함]**
	- 테스트 실패 시, 어떤 값이 들어오고 왜 틀렸는지 매우 상세한 디버깅이 가능하다.
- **[강력한 Fixture 시스템]**
	- 테스트 전후에 필요한 환경설정(DB 연결, 더미 뎅이터 생성 등)을 모듈화하여 효율적으로 재사용할 수 있다.
- **[풍부한 생태계 플러그인]**
	- 코드 커버리지 측정(`pytest-cov`), 병렬 테스트(`pytest-xdist`), 장고 연동(`pytest-django`)등 수천 개의 플러그인을 지원한다.
## 정의

> **"간단하고 확장 가능한 테스트를 작성하기 위한 파이썬 프레임워크"**

- **[기본 구조의 단순화]**
	- 함수 이름 앞에 `test_`만 붙이면 바로 테스트 케이스로 인식한다.
- **[하위 호환성]**
	- 기존 `unittest`나 `nose`로 작성된 테스트 코드도 수정 없이 `pytest`로 그대로 실행할 수 있다.

## `unittest`와의 비교

- **[`unittest`]**
```
import unittest

class TestString(unittest.TestCase):
    def test_upper(self):
        self.assertEqual('foo'.upper(), 'FOO')
```
- **[`pytest`]**
```
def test_upper():
    assert 'foo'.upper() == 'FOO'
```
## 동작 과정

### 1. 테스트 발견
- `test_*.py` 또는 `*_test.py` 형태의 파일명을 찾는다.
- 파일 내부에서 `test_`로 시작하는 함수나 클래스 내부의 `test_` 메서드를 수집한다.
### 2. Fixture 및 설정 로드
- 테스트 실행 전, 필요한 환경(DB, Mocking 등)을 설정하는 `@pytest.fixture` 함수를 먼저 로드한다.
- 파일 전역이나 `conftest.py`에 정의된 공통 설정들을 적용한다.
### 3. 테스트 실행 및 단언문 검증
- 수집된 테스트 함수들을 하나씩 실행한다.
- 실행 중 `assert`문을 만나면 조건이 `True`인지 확인한다. `False`일 경우 `AssertionError`를 발생시키고, 해당 테스트를 실패로 기록한다.
### 4. Fixture 정리
- 테스트가 끝난 후 사용한 모든 자원을 반납한다.
- Fixture 내부의 `yield` 키워드 다음에 오는 코드들이 이 단계에서 실행된다.
### 5. 결과 보고
- 모든 테스트가 끝나면 터미널에 요약 결과를 출력한다.
- 성공(`.` 또는 `PASSED`), 실패(`F`, 또는 `FAILED`), 스킵(`s`, 또는 `SKIPPED`)등의 기호와 함께 총 소요 시간 및 실패 원인을 시각적으로 보여준다.
