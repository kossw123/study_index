
## 왜 필요한가?

- 런타임 에러에 대해 걱정할 필요가 없다. 컴파일 에러에서 다 잡아주니까.
- 덜 장황하다. 즉, 가독성이 좋다.
- ORM을 안다면 굳이 SQL을 알 필요가 없다.
- OOP를 중심으로 설계하여 코드의 가독성이 좋아진다.
- DB Schema가 변경되더라도 엔티티 클래스만 수정해주면 유지보수가 편해진다.
  

## 정의

객체와 DB 사이를 메타데이터(부가정보)를 이용하여 필요한 것들을 자동으로 매핑해주는 시스템이다.

보통 서버 코드와 DB 쿼리는 구조부터 완전히 다르다.
파이썬은 데이터와 기능을 묶은 객체(Object) 중심구조를 가지고
DB는 column과 attribute를 행렬로 정렬한 2차원 테이블 구조를 가지고 있다.

그래서 이 둘 사이를 자동으로 매핑해주는 ORM을 사용하면 다음과 같은 장단을 얻을 수 있다.

장점
- 생산성 향상: 당연히 쿼리를 길게 작성할 필요가 없어져서 가독성이 향상된다.
- 유지보수 용이: DB가 변경되도 클래스만 수정하면 되서 간단하다.
- DB 종속성 분리: 굳이 mysql이 아니더라도 postgreSQL로 바꿀 경우 코드를 거의 수정할 필요가 없어진다.

단점
- 성능 한계: 결국 ORM이 내부적으로 SQL을 만들어서 복잡하거나 대용량 데이터 처리할 때는 성능이 떨어지거나 비효율적인 쿼리가 발생할 수 있다.
- 또 학습을 해야한다.


## 프로젝트에서는 어디에서 사용하는가?

- sqlmodel이라는 ORM을 프로젝트 전반적으로 사용한다.
- 보통 Repository라는 이름이 붙은 객체에서 모두 사용된다.
- Application Layer와 Transaction 관리 객체인 UnitOfWork 객체와 통신하며, Repository에 접근한 다음 commit을 한다.
