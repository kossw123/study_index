## 정의

로드 밸런싱이라는 기술이 있다.
기본적으로는 서버에 부하를 줄이기 위한 기술이다.
그래서 서버와 또 다른 컴퓨터일 수 있고, 서버에 설치하는 프로그램일 수도 있다.

- 하드웨어 로드밸런서는 고성능 컴퓨터에 장비를 다는 것을 의미한다.
	보통 L4 / L7 스위치라고 부르는 랙(Rack)장비를 의미한다.
	이는 하드웨어 수준에서는 엄청난 양의 트래픽을 감당할 수 있어서 성능이 압도적으로 좋지만, 장비 자체가 수천만원을 호가한다.

- 소프트웨어 로드밸런서는 보통 Nginx나  Apache, HAProxy같은 프로그램을 의미한다.
	- 성능이 좋은 컴퓨터를 구해 이 프로그램을 실행하면 그 컴퓨터가 바로 로드밸런서 역할을 하게 된다.
	- 하지만 하드웨어 로드밸런서에 비해서는 한계가 있다.
	이 프로그램들은 진화하면서 
	- “내 뒤에 있는 다른 서버로 요청을 토스하는 기능(프록시)”과 
	- “그 요청을 여러 대에 나누어 보내는 기능(업스트림)”을 
	- 탑재하게 되었기 때문에 로드밸런서라고 불린다.


## 동작 과정


Nginx와 Apache는 본인 혼자서 일을 다 처리하지 않는다.
대신에 사용자의 요청을 받아서 뒷 단에 있는 WAS 결합형 서버(FastAPI 등)에 대신 전달하고 그 결과만 받아오는 대리인(Proxy) 역할을 할 수 있다.

그렇다면 앞 단에 Nginx 1대, 뒷 단에 FastAPI 3대가 있다고 가정해보자.
Nginx는 “내 뒤에 서버가 3대가 있으니 순서대로 나눠 보내라”라고 대리인(Proxy)으로써 설정을 추가하는 순간 Nginx는 로드밸런서로 돌변하게 된다.

아래 코드는 Nginx의 업스트림 실제 코드 예시다.

// 1. 내 뒤에 부하를 분산 처리할 WAS 서버들을 그룹으로 묶습니다 (Upstream)
upstream my_was_cluster {
    server 192.168.0.10:8080;  # 1번 WAS 서버
    server 192.168.0.11:8080;  # 2번 WAS 서버
    server 192.168.0.12:8080;  # 3번 WAS 서버
}

server {
    listen 80; # 사용자가 들어오는 문 (포트)

    location / {
        # 2. 사용자가 들어오면 위에서 지정한 WAS 그룹으로 요청을 토스합니다!
        proxy_pass http://my_was_cluster;
    }
}


# 비교

보통 소프트웨어 로드밸런서는 Nginx를 많이 쓰는데, Apache와 비교해서 장단을 알아보자.
- Apache는 요청이 들어올때마다 프로세스나 스레드를 새로 만들어 자원을 낭비한다.
- Nginx는 Event-Driven 구조로 동작해 적은 자원을 가지고 수만 명의 동시 접속 요청을 받을 수 있다.
