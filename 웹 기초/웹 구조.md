

## 왜 필요한가?

- 현대에 와서는 동적 웹 프로그래밍 구조도 여러 형태로 발전했다.
- 하드웨어 진화에 따라 할 수 있는 범위가 넓어졌기 때문에, 구조도 진화했다.

## 정의

# 모놀리식

====================================

WAS 갯수: 1
DB 갯수: 1
추천 상황: 초기 스타트업, 단순한 서비스

====================================

소프트웨어의 모든 기능을 하나의 단일 프로젝트로 개발, 하나의 실행파일로 빌드해서 배포하는 전통적인 방법이다.
그래서 기능도 하나의 폴더로 구성되는 경우가 많다.

기본적으로 동적 웹 프로그래밍 구조를 모놀리식이라고 부른다.
그런데 왜 굳이 서로 다른 것처럼 얘기할까?란 질문에 다음과 같이 답변할 수 있겠다.

동적 웹 프로그래밍이라는 개념에서의 구조와 모놀리식 구조는 서로 바라보는 관점이 다르다.
동적 웹 프로그래밍은 서로 통신을 주고받는 결과에 대한 이야기라면, 모놀리식은 인프라에 어떻게 배치할 것인가에 대한 이야기다.

“모놀리식의 가장 중요한 이념은 주소가 하나고, 로직이 하나고, 저장소가 하나다 라는 것이다.”

이런 개념은 하나의 파이프라인만 잘 관리하면 개발과 유지보수가 편하다는 장점이 있다.
또한 단점도 파이프라인이 하나라서 하나라도 잘못된다면 모든 기능이 정지된다.


# 모듈러 모놀리스

====================================

WAS 갯수: 1
DB 갯수: 1(또는 스키마 분리)
추천 상황: 코드 복잡도를 낮추고 싶은 중소규모 서비스

====================================


모놀리식의 한계인 하나의 파이프라인 때문에 장애가 생기면 발생하는 문제를 해결하기 위해 다음과 같이 구성한다.

1. 배포와 인프라, 즉 단일 프로젝트로 개발하고 하나의 실행파일로 배포한다.
2. 그러나 단일 프로젝트에 포함되어야 할 기능들은 단일 프로젝트에서 여러 폴더로 계층을 만들어서 구현한다.

모놀리식의 장점은 가져오면서 소스코드 구성은 보기 쉽게 기능별로 계층을 나눠서 구혆한다는 뜻이다.

장점을 보면, 모놀리식과 동일한 구조를 가지고 있다.

클라이언트 <-> 웹 서버 <-> WAS <-> DB

1. 그래서 따로 복잡한 분산 인프라 기술이 필요없기 때문에 진입장벽이 낮다.
2. 모듈간 통신이 HTTP가 아닌 메모리 연산으로 이뤄져 처리속도가 매우 빠르기도 하다.
3. 계층을 잘 구성하면 트랜잭션의 무결성을 보장할 수 있다.
4. MSA로 전환하기도 쉽다. 이미 소스코드는 기능별로 분산화 되어있기 떄문에 이식만 하면 된다.


그러나 한계도 명확하다. 

1. 모놀리식을 골자로 삼아서 기술 스택이 하나의 프로그래밍 언어로 되어있다.
2. 코드는 격리되었으나, 배포 단위가 하나라서 고칠 때마다 다시 빌드하고 배포해야 한다.
3. 특정 모듈에서 메모리 누수가 발생한다면 전체가 죽는다.



# 마이크로서비스 아키텍처

====================================

WAS 갯수: 수십 ~ 수백 개
DB 갯수: 서비스 당 하나씩
추천 상황: 대기업, 대규모 트래픽, 거대한 개발 팀

====================================



클라이언트 <-> 웹 서버 <-> WAS  <-> DB
					 <-> WAS <->
					 <-> WAS <->
					 <-> WAS <->

이런식으로 확장해 나가는 구조를 마이크로서비스 아키텍처라 부른다.
WAS만 확장하는게 아닌 DB도 확장하여 구현할 수 있다.
이 구조의 특징은 각 WAS마다 담당하는 기능이 있다는 것이다.

각 WAS가 담당하는 기능에 장애가 생겨도 다른 기능은 멀쩡히 살아있다.
또한 각 기능마다 언어 스택이 달라도 상관없이 돌아간다.
그리고 특정 부분에 트래픽이 몰리면 필요한 부분만 서버를 늘릴 수 있다.


# 서버리스

====================================

WAS 갯수: 없음(클라우드 시스템 활용)
DB 갯수: 필요한 만큼 연동
추천 상황: 이벤트성 작업, 백그라운드 처리, 배치 작업

====================================

이름 그대로 서버가 항상 켜질 필요가 없이, 요청이 들어오면 
“새 컴퓨터를 만들고 요청이 끝나면 폐기”하는 방식으로 동작한다.

기본적으로 MSA와 같은 구조를 띄지만, 별도의 WAS가 없다.
그러므로 이 부분은 AWS, Oracle과 같이 대기업의 클라우드 시스템을 이용해 매꾼다.

그러면 최종적으로 정리해보자.

1. 서버리스는 MSA의 핵심사상을 이어받아 기능을 함수 단위(FaaS)로 쪼갠 구조를 가진다.
2. 그러나 로드밸런서는 있지만, 업스트림을 대상으로 할 WAS가 없다.
    1. 이 부분은 AWS, Oracle과 같은 클라우드 시스템이 대신한다.
3. DB는 따로 연결한다.


## 프로젝트에서는 어디에서 사용하는가?
