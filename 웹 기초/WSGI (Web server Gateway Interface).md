
## 왜 필요한가?

- 파이썬은 원래 웹 서버에 특화된 언어가 아니기 때문이다.

> Nginx나 Apache 같은 전문 웹 서버는 C/C++로 작성되어 HTTP 데이터를 빠르게 처리하지만, 파이썬 프로그램은 웹 브라우저의 HTTP 요청을 직접 받아서 해석할 수 없다.
> 
> 이 때, WSGI라는 규격화된 규칙으로 브라우저의 HTTP 텍스트 요청을 파이썬이 다룰 수 있는 객체로 변환해 주기 때문에, 파이썬 코드가 동작할 수 있다.

- 표준 규약을 중간에 삽입하기 때문에, HTTP 요청이 파이썬 프로그램에 도달하기 전, 후에 공통적인 작업을 쉽게 끼워 넣을 수 있다(Middleware).


## 정의

- [python web application]과 [web server]가 서로 통신할 수 있게 해주는 표준 규격(인터페이스/규약)이다.

`"즉, 웹 서버와 파이썬 웹 프레임워크 간의 표준 연결 통신 규격이다."`


1. **[프로그램]** 이 아니라, **[문서]** 다.
	- WSGI는 설치하는 소프트웨어가 아니라 설명서이자, 프로토콜이다.
2. 동기식(Synchronous) 단일 호출 구조다.
	- 단방향 HTTP 요청을 응답한 뒤에는 연결을 끊는다.
3. 코드 레벨에서의 정의(호출 규격)다.
	- 파이썬 언어 관점에서는 WSGI는 **[두 개의 인자를 받고 반복 가능한 객체(iterable)를 반환하는 콜러블(Callable: 함수나 메서드)]** 로 정의된다.


## 동작 과정

- 단방향 HTTP 요청이 들어오면 응답을 보내고 연결을 끊는 구조로 구성되어 있다.


## ASGI와의 차이점

| 비교 항목         | WSGI                        | ASGI                                |
| ------------- | --------------------------- | ----------------------------------- |
| **핵심 프로토콜**   | 단일 HTTP 요청-응답만 지원           | HTTP, WebSockets, 채팅 프로토콜 지원        |
| **연결 방식**     | 요청 완료 시 연결 즉시 종료            | 연결이 끊어질 때까지 장시간 지속 가능               |
| **애플리케이션 구조** | 동기식 단일 함수 호출 구조             | 비동기식 메시지 송수신 이벤트 루프 구조              |
| **데이터 처리**    | 요청 바디를 한 번에 동기식으로 읽음        | 대용량 데이터를 청크 단위로 실시간 스트리밍            |
| **대표 프레임워크**  | Django (기본), Flask, Pyramid | FastAPI, Django Channels, Starlette |
