
## 왜 필요한가?

- 기존의 WSGI 방식으로는 [비동기 처리]와 [웹 소켓(실시간 통신)]을 효율적으로 구현할 수 없다.
- WSGI는 HTTP 요청을 받으면 응답을 주고 끝나는 **[단방향 구조]** 만 지원한다.
- 그러나 현대에서는 채팅, 알림, 주식차트, 온라인 게임 등 실시간 구조가 중요하게 대두되기 때문에 서버와 클라이언트가 연결을 유지하며 양방향 통신을 해야한다.
- 이 문제에서 ASGI는 웹 소켓(Web Socket) 프로토콜을 표준으로 지원해, 실시간 양방향 연결을 완벽히 지원한다.


## 정의

- 비동기 및 동기 처리를 모두 지원하도록 설계된 Python Web Application과 서버 간의 표준 인터페이스다.

>**[착각해선 안되는게, ASGI는 규격이지, 프레임워크가 아니다.]** 
>즉, FastAPI, Django는 ASGI를 구현한 프레임워크다.


- 보통 FastAPI, Django 등이 ASGI라고 불리며 실시간 통신 및 고성능 처리를 가능하게 한다.
- Parallelism(병렬성)이 아닌 **[Concurrency(동시성)]** 을 지원한다.


## 동작 과정

- **[연결 상태를 이벤트로 분해해서 처리한다.]**
	- 연결 수신, 데이터 수신, 연결 종료 등
- 이를 위해 `scope`, `receive`, `send`와 같은 비동기 Callable(함수)를 사용한다.

## 프로젝트에서는 어디에서 사용하는가?

- FastAPI 프레임워크를 사용함으로써, ASGI 규격에 맞는 웹 앱을 사용하고 있다.
