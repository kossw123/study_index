## 왜 필요한가?

1. **[기억의 한계 극복]**
	- [문제점:]
		- 네이버에 접속할 때 `://naver.com` 대신 `223.130.200.104`라는 복잡한 IP 주소를 외워서 주소창에 입력해야 한다.
	- [DNS 해결책:]
		- 전화번호부에 '홍길동'을 검색하듯, 문자로 된 도메인 이름만 외우면 수많은 사이트에 쉽게 접속할 수 있다.
2. **[IP 주소가 바뀌어도 유연한 대처 가능]**
	- [문제점:]
		- 사이트 IP가 바뀔 때마다 전 세계 사용자들에게 "우리 주소가 바뀌었으니 이제 새로운 숫자로 접속하세요"라고 알려야 한다.
	- [DNS 해결책:]
		- 전화번호부에 '홍길동'을 검색하듯, 문자로 된 도메인 이름만 외우면 수많은 사이트에 쉽게 접속할 수 있다.
3. **[트래픽 분산과 로드 밸런싱 (안정성)]**
	- [문제점:]
		- 대형 웹사이트는 수천만 명의 사용자를 감당하기 위해 여러 대의 서버를 운영한다.
	- [DNS 해결책:]
		- DNS는 하나의 도메인 이름에, 여러 개의 IP주소를 연결할 수 있어, 사용자가 접속할 때마다 서로 다른 IP 주소로 연결해줘서 특정 서버에 사람이 몰리는 것을 방지한다.
4. **[브랜드 가치와 신뢰성 유지]**
	- 기업은 자신의 정체성을 담은 도메인 이름(예: `apple.com`, `samsung.com`)을 사용하여 브랜드를 홍보하고 신뢰감을 줄 수 있다.

## 정의

- HTTP는 숫자 형태의 IP주소를 통해(125.72.211.123 등) 브라우저를 인식한다.
- 그러나 사용자가 보기에는 인식하기 어려운 점을 꼽아, 사람이 읽을 수 있는 이름으로 바꾸는 것이 Domain Name이다.
- 이렇게 IP주소를 이름으로 바꾸는 것과, 이름을 IP주소로 바꾸는 것을 DNS라고 한다.

## 동작 과정

1. [DNS 리졸버(DNS Resolver):]
	- 사용자의 요청을 가장 먼저 받아 다른 DNS 서버들을 차례로 방문해, 주소를 대신 찾아준다.
2. [루트 네임서버(Root Nameserver):]
	- IP 주소를 찾기 위한 첫 번째 단계로, 최상위 도메인(TLD) 서버의 주소를 알려준다.
3. [TLD 네임서버(Top-Level Domain):]
	- 도메인의 확장자(`.com / .net / .kr`등)를 관리하며, 해당 도메인의 상세 정보를 가진 서버로 안내한다.
4. [권한 있는 네임서버(Authoritative Nameserver):]
	- 해당 도메인의 실제 IP주소가 저장되어 있는 최종 목적지다.
	- 이곳에서 IP 주소를 리졸버에게 돌려준다.
