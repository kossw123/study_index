
## 왜 필요한가?

- 전통적인 HTTP 통신은 클라이언트가 요청(Request)을 보내야 서버가 응답(Response)을 줄 수 있는 단방향 구조다.
- 실시간 데이터가 중요시 여겨지면서 브라우저가 주기적으로 서버에 데이터를 요청해야 했고, 이는 엄청난 낭비를 초래했다.

## 정의

> 브라우저와 서버 간, 단 한번만 연결을 맺으면, 양방향으로 실시간 데이터를 자유롭게 주고 받을 수 있도록 만든 네트워크 프로토콜이다.

## 특징

1. 양방향 통신
2. 실시간
3. 지속적인 연결

## 동작 과정

Step 1. 웹소켓 핸드셰이크 (Handshake)

- 브라우저가 서버에 일반 HTTP 요청을 보내면서 헤더에 `Upgrade: websocket`과 `Connection: Upgrade`를 담아 보냅니다. "우리 이제 웹소켓으로 대화 방식을 바꾸자"고 제안한다.

Step 2. 프로토콜 전환 (Switching Protocols)

- 서버가 이를 지원한다면 `HTTP 101 Switching Protocols`라는 응답을 보냅니다. 이 순간부터 HTTP 연결이 웹소켓 연결로 업그레이드된다.
- 주소창의 프로토콜도 `http://`가 아닌 **`ws://`**(보안 처리는 `wss://`)로 바뀐다.

Step 3. 양방향 데이터 전송

- 이제 HTTP 헤더 같은 무거운 짐을 다 버리고, 가벼운 데이터 단위(Frame)만 주고받으며 실시간 대화를 나눈다.

Step 4. 연결 종료 (Close)

- 대화가 끝나면 어느 한쪽이 Close 프레임을 보내 연결을 정상적으로 닫는다.
