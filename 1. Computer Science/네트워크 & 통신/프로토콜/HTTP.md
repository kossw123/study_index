## 왜 필요한가?

- 웹은 이론상 지구 반대편까지 데이터를 주고 받을 수 있다.
- 데이터를 정확히 주고 받으려면, 정확히 어느 주소로 무엇을 줘야할지 알아야 한다.
- HTTP는 이런 데이터를 주고받는 구체적인 약속이다.

## 정의

-  http는 웹에서 이루어지는 모든 데이터의 교환방법이다.

## 동작 과정

교환방법이라고 하는데 데이터를 어떻게 교환할까?

프로그래밍에서는 보통 다음과 같이 메모리 안에서 위치를 바꾼다.

```
var v1 = 1
var v2 = 2
var temp

temp = v1
v1 = v2
v2 = temp
```

> 그렇다면 웹에서 데이터는 뭘까? 변수일까 값인가?
> 값이다. 이 값을 메시지라고 한다.

텍스트나 바이너리 값 등을 서버에서 정의한대로 값을 전달하고 값에 대한 위치값이나 이미지를 정해서 전달한다.

즉, **[서버에 값을 정의한 대로 클라이언트에서 요청하면 복사본을 넘긴다]** 는 것이다.

>예시로 클라이언트에서 .jpg라는 데이터가 필요하다고 url주소라는 값을 보낸다.
>서버에서는 해당 url값을 받아 클라이언트가 원하는 .jpg 데이터를 보낸다.

### 메시지의 구조

Http 메시지의 실제 요청 메시지 구조는 다음과 같다.

```
POST /login HTTP/1.1  // 시작줄
Host: ://example.com  // 2~5줄은 헤더라 한다.
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Content-Type: application/json
Content-Length: 45

{  //여기서 부터 바디
"userId": "user123",
"password": "mypassword"
}
```

## HTTP/1.0 (1996년)

- [기반 프로토콜]
	- TCP
- [통신방식 특징]
	- 파일 1개당 연결 1번 맺고 끊기
- [주요 한계점]
	- 너무 느림 (매번 새로 연결)
- [방식]
	- 네이버 메인 페이지에 접속할 때 글자, 고양이 이미지, 로고 이미지 등 파일 1개를 가져올 때마다 매번 컴퓨터간의 악수(TCP 연결)를 새로 하고 끊었습니다.
- [문제점]
	- 웹페이지에 이미지와 데이터가 많아지면서 심각하게 느려지는 문제가 발생했습니다

## HTTP/1.1 (1997년)

- [기반 프로토콜]
	- TCP
- [통신방식 특징]
	- 연결 하나를 계속 유지하며 재사용
- [주요 한계점]
	- 앞의 파일이 밀리면 뒤도 밀림
- [개선]
	- 매번 연결을 끊지 않고, 한 번 연결하면 필요한 파일들을 줄줄이 연속으로 다운로드할 수 있게 되었습니다.
- [문제점]
	- 순서대로 데이터를 받다 보니, 앞선 첫 번째 이미지 다운로드가 서버 문제로 지연되면 뒤에 있는 두 번째, 세 번째 데이터도 통째로 기다려야 하는 HOLB(Head of Line Blocking, 대기선 정체) 문제가 있었습니다.

## HTTP/2 (2015년)

- [기반 프로토콜]
	- TCP
- [통신방식 특징]
	- 하나의 연결로 여러 파일 동시 전송
- [주요 한계점]
	- TCP 자체의 패킷 유실 시 멈춤
- [개선]
	- 정체 문제를 해결하기 위해 데이터를 잘게 쪼개어 하나의 연결 통로 안에서 여러 개의 파일을 동시에(병렬로) 주고받는 다중화(Multiplexing) 기술을 도입했습니다. 
	- 또한, 무거운 헤더(Header) 정보를 압축해서 전송량을 크게 줄였습니다.
- [문제점]
	- HTTP 자체의 정체는 해결했으나, 인터넷 연결 기반인 TCP 프로토콜 자체의 한계로 인해 데이터 패킷이 하나라도 유실되면 전체 통신이 잠시 멈추는 현상이 여전히 존재했습니다.

## HTTP/3 (2022년)

- [기반 프로토콜]
	- UDP (QUIC)
- [통신방식 특징]
	- HTTP2보다 획기적으로 빠른 연결 및 무정체 통신
- [주요 한계점]
	- 많은 자원 소비와 물리적 소비까지는 막아주지 못한다.
- [장점]
	- 패킷이 중간에 유실되어도 다른 데이터 전송은 멈추지 않고 계속 진행됩니다. 
	- 연결을 맺는 속도가 비약적으로 빨라져서, 모바일 기기로 지하철이나 엘리베이터 등 와이파이와 LTE가 자주 바뀌는 불안정한 네트워크 환경에서도 끊김 없이 매끄럽게 통신합니다.
