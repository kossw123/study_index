## 왜 필요한가?

[ref + log]

- 실수로 지워버린 커밋, 브랜치, 잘못 진행된 reset이나 rebase를 다시 되살리기 위해 필요하다.
- Git에서 제공하는 최후의 보루이자, [완벽한 블랙박스 기록 장치]로써 로컬에서 일어난 모든 Git 포인터의 이동 이력을 빠짐없이 기록한다.
	- `git reset --hard`로 지워진 커밋 복구
	- 실수로 삭제한 브랜치 복구
	- 실패한 rebase나 merge 이전으로 되돌림

## 정의

- 로컬 저장소에서 HEAD 포인터나 브랜치 래퍼런스가 변경될 떄마다, 그 이동경로를 빠짐없이 기록하는 Git 내부의 블랙박스다.

## 동작 과정


1) **[전체 이동 기록 확인]**

```
$ git reflof
```

2) **[실수로 지워진 커밋 복구]**

```
$ git reset --hard HEAD~1 // 실수로 지워진 커밋
$ git reset --hard HEAD@{2} // reflog 인덱스 이름으로 복구하기
$ git reset --hard a1b2c3d // commit id로 복구하기

```

3) **[실수로 삭제한 브랜치 복구]**

```
$ git reflog // 1. 기록을 열어 지워진 브랜치의 마지막 커밋 ID를 찾는다.
$ git branch feature e53dg3h // 2. 찾은 커밋 ID를 기준으로 새 브랜치를 다시 만든다.
```

4) **[안전하게 과거 상태만 복구]**

```
$ git checkout HEAD@{2} 
// 작업 디렉토리가 잠시 과거 상태로 바뀐다.
// 다시 현재 브랜치로 switch하면 현재 상태를 복구할 수 있다.
```
