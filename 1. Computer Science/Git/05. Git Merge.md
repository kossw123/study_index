## 왜 필요한가?
- 여러 사람이 동시에 작업한 코드(브랜치)를 하나로 모으기 위해 필요하다,
## 정의

> 분기된 두 개 이상의 개발 내역(브랜치)을 하나로 통합하는 Git 명령어다.

- 이력 병합
	- 서로 다른 브랜치의 커밋 들을 분석해 하나의 브랜치로 모은다.
- 통합 커밋 생성
	- 두 브랜치를 합치고 병합 완료를 뜻하는 새로운 merge commit을 자동으로 생성한다.
- 충돌 감지
	- 같은 파일의 동일한 위치를 양쪽에서 동시에 수정하는 경우, 사용자에게 충돌을 알린다.

## 동작 과정

### Fast-forward

기본 브랜치에서 분기된 이후 main 브랜치에 새로운 커밋이 전혀 쌓이지 않았을 떄 적용된다.

```
			  D -- E (feature)
			/
A -- B -- C (main)
```

이 상태에서 

1. main 브랜치가 새로운 커밋이 없고 
	
2. feature 브랜치에 최신 커밋이 있는 상태에서 
	
3. merge를 한다면

다음과 같이 변경된다.

```
A -- B -- C -- D -- E (main, feature)
```
### 3-way merge

main, feature 브랜치 모두 새로운 커밋이 쌓였을 때 적용된다.

```
  D -- E (feature)
 /
A -- B -- C (main)
```

> 공통 조상을 기준(A)으로 양 브랜치의 변동 사항을 비교하며,
> 병합이 완료되면 두 갈래의 역사를 합친 새로운 머지 커밋(F)이 생신다

```
   D ------- E (feature)
  /           \
A -- B -- C -- F(main)
```

### 3-way merge 도중, 두 브랜치가 동일한 파일의 같은 줄을 서로 다르게 수정했다면?

git이 자동으로 변경사항을 감지하여 합치는 것을 막고, 충돌(conflict)를 알린다.

### Fast-forward가 되는걸 막고, 3-way merge로 하고 싶다면?

```
/path>(main)
# git merge feature --no-ff
```
