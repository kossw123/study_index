
## Problem.

- 현재 한번에 두 가지 수정 작업을 하나의 commit에 한번에 올렸다.

```
현재 git commit graph

11bafff -> 1773070 -> d2e5d82 -> 4b0b544 -> d19b8e1(문제 commit)
```

## Sovle.

> 최근 커밋을 취소하고, 두 가지 작업물을 나눠서 하나씩만 올린다.

### [1. 최근 commit 취소]

- `git reset HEAD^`
	- 가장 최근 commit을 취소하고 코드를 작업 전(unstaged) 상태로 돌린다.

### [2. github와의 동기화]

```
> 두 가지 경우로 나뉜다.
> 1. 브랜치를 혼자 쓰는 경우
> 2. 브랜치를 여러 명이서 쓰는 경우
```

1. 브랜치를 혼자 쓰는 경우
	- `git push origin <브랜치이름> --force-with-lease`

> [`--force` 대신 `--force-with-lease`를 쓰는 이유]
> `--force는` 무조건 덮어쓰지만, `--force-with-lease`는 내가 모르는 사이에 Github에 다른 사람이 올린 commit이 있다면 작업을 중단시킨다.


2. 브랜치를 여러 명이서 같이 쓰는 경우
	- 이미 `reset`을 진행한 상황이면, `reset`을 복구 시키고, `revert`를 사용해야 한다.
```
$ git pull origin <브랜치 이름>  // 원격 저장소의 최신 상태를 가져오기
$ git revert <commit ID>  // 원격 저장소의 commit을 취소한다는 commit push
$ git add . 또는 git add -p  // 특정 파일을 add
$ git commit -m <commit 메시지> 
$ git push origin <브랜치 이름> 
```


## [3. force push 후 팀원의 로컬이 꼬였다면?]


- 만약 `git push <브랜치 이름> --force-with-lease`을 했는데, 다른 팀원이 이미 그 브랜치를 받고 작업 중이었다면 그 팀원은 아래 명령어로 동기화를 해야한다.

```
$ git fetch origin
$ git reset --hard origin/<브랜치 이름>
$ git commit -m [분할 커밋1]
$ git commit -m [분할 커밋2]
	...
$ git commit -m [분할 커밋5]
```

> 이 명령어를 실행하면 로컬에서 작업 중이던 commit 하지 않은 코드가 모두 사라지기 때문에, 반드시 백업(`git stash`)한 뒤 실행해야 한다.
