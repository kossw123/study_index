## 왜 필요한가?

이미 원격 저장소에 업로드(push)된 잘못된 커밋을 안전하게 취소하고 되돌리기 위해 필요하다.

- 협업 중인 공유 브랜치의 역사 보존
- 잘못된 작업의 취소 기록(히스토리) 남기기
- 원격 저장소 강제 푸시 (`--force`) 방지

## 정의

- 과거 특정 커밋 변경 사항을 되돌리는 [반대 성격의 새로운 커밋]을 생성하는 명령어다.
	- 기록 보존형 취소 : 
		- 과거의 잘못된 기록을 지우지 않고 그대로 둔 채 코드만 원상복구한다.
	- 안전한 협업 : 
		- github에 push된, 팀원과 공유중인 브랜치에서 안전하게 실수를 수습할 수 있다.
	- 일반 push 가능 : 
		- 히스토리가 앞으로 전진하는 형태이기 때문에 강제 푸시(`--force`)없이 `git push`


### Reset vs Revert

```
A -- B -- C 순서로 커밋 후 github에 push까지 완료한 상태에서 
> 잘못 만든 C 커밋을 취소 하고 싶을 떄
```

1) `git reset`을 쓸 경우

```
$ git reset <B commit id>
```

`git reset <B commit id>`을 한 경우 C 커밋을 히스토리에서 아예 지워버리고 B로 돌아간다.

```
A -- B
```

2) `git revert`를 쓸 경우

```
A -- B -- C -- Revert 'C' (현재 코드는 B 상태와 동일)
```

C 커밋은 역사에 그대로 두고, C에서 수정한 내용을 정반대로 뒤집어 원상복구 시키는 새로운 커밋 Revert 'C'를 뒤에 이어 붙인다.

## 동작 과정

```
$ git revert HEAD // 직전 커밋 하나만 취소하기
$ git revert <과거 commit id> // 과거 특정 커밋 취소
$ git revert --no-edit <commit id> // 커밋 메시지 창 띄우지 않고 바로 취소하기
$ git revert -n HEAD~3..HEAD // 여러 커밋을 한 번에 모아서 취소하기
```
