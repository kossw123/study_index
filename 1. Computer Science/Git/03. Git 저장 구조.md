## 동작 과정

프로젝트를 생성하여 git init을 통해 git을 생성하면 다음과 같은 구조를 가지게 된다.

```
project
├─ .git
│ ├─ objects (폴더)
│ ├─ refs (폴더)
│ └─ HEAD (파일)
└─ code files
```
## object

“object에는 blob, tree, commit을 저장한다.”

그리고 다음과 같은 위치를 가지게 된다.

```
.git/objects/ab/12345...
```

- ab, 123456은 SHA-1 해시값을 나눠서 저장한 것을 의미한다.    
- 예를 들어 ab1234567890abcdef1234567890abcdef123456 라는 객체 ID가 있다면 Git은 다음과 같이 저장한다.
- `.git/objects/ab/1234567890abcdef1234567890abcdef123456`
- 즉 다음과 같이 저장된다.

```
.git
└ objects
└ ab ← 해시 앞 2자리
└ 1234567890... ← 나머지 38자리
```

## ref

“ref에는 브랜치의 위치를 저장한다.”

```
refs/heads/main
refs/heads/dev
```

main 브랜치와 dev라는 브랜치가 있다는 것을 알린다.

> 여기서 브랜치라는 개념이 생긴 이유는 단순하게, 이전 코드로 돌아가기 위한 포인터가 필요하기 때문이다.

즉, 브랜치는 특정 시점을 가리키는 단순한 포인터다.

## head

”HEAD에는 현재 브랜치를 가져온다.”

- HEAD는 현재 작업중인 브랜치를 가리키며, 그 브랜치가 최신 commit의 위치를 가리킨다.
- ref에서 현재 내가 작업하고 있는 브랜치를 가져와 저장한다.
- 기본적으로 main 또는 master 라는 이름의 브랜치가 기본적으로 생성된다.

Git 내부 기준으로 더 정확한 정의는

"HEAD는 현재 체크아웃된(선택된 브랜치를 가리킨다) commit의 위치를 나타내는 reference다.”

원래라면 HEAD는 현재 브랜치를 가리키는 포인터라고 알고 있었지만, 항상 브랜치를 가리키진 않기 때문이다.
