## 왜 필요한가?

- **보안 및 은닉:** 클라이언트나 서버의 실제 네트워크 정보(IP 주소 등)를 숨겨 외부 공격으로부터 보호할 수 있다.
- **캐싱(Caching):** 자주 요청되는 데이터나 정적 파일을 프록시 단에서 저장(캐시)해 두어 통신 속도를 비약적으로 높인다.
- **트래픽 분산:** 리버스 프록시 설정을 통해 여러 대의 애플리케이션 서버로 부하를 분산(로드 밸런싱)할 수 있다.
- **액세스 제어:** 네트워크 요청을 검사하여 유해 사이트 접속을 차단하거나 방화벽 역할을 수행할 수 있다.

## 정의: 포워드 프록시 vs 리버스 프록시

프록시(Proxy)는 '대리인'이라는 뜻으로, 네트워크 상에서 누구의 요청을 대리하느냐에 따라 명확히 구분된다.

### 1. 포워드 프록시 (Forward Proxy)
- **대변하는 대상:** 클라이언트 (Client)
- **위치:** 클라이언트와 내부 망 사이 (클라이언트 관문)
- **핵심 역할:** 클라이언트가 외부 인터넷 서버에 접근할 때 중간에서 요청을 가로채 대신 보내준다.
- **주요 목적:** 
  - 외부 서버에게 클라이언트의 실제 IP를 숨김 (익명성 보장).
  - 사내 네트워크 등에서 특정 유해 사이트 접근 차단.
  - 자주 방문하는 외부 사이트의 리소스 캐싱.
- **예시:** 기업 사내 방화벽, VPN, 프록시 서버 설정 등.

### 2. 리버스 프록시 (Reverse Proxy)
- **대변하는 대상:** 서버 (Server)
- **위치:** 외부 인터넷망과 진짜 서버(WAS) 사이
- **핵심 역할:** 클라이언트는 리버스 프록시를 진짜 서버로 알고 요청을 보내고, 리버스 프록시는 그 요청을 받아 뒤편의 진짜 내부 서버들에게 안전하게 전달(Toss)한다.
- **주요 목적:** 
  - 외부 노출을 막아 진짜 서버들의 IP 주소와 구조를 숨김 (보안).
  - 여러 대의 WAS 서버로 요청을 나누어 주는 로드 밸런서 역할.
  - SSL/TLS 암호화/복호화(HTTPS) 처리를 대행하여 WAS의 연산 부담 경감.
- **예시:** Nginx, Apache HTTP Server, HAProxy 등.

## 아키텍처 흐름 및 실무적 이해

### 💡 Vite의 `server.proxy` 설정은 무엇일까?
- 프론트엔드 개발 환경(Vite, React 등)에서 설정하는 프록시는 포워드 프록시가 아니라 **개발 서버가 제공하는 '리버스 프록시' 기능**이다.
- 브라우저가 프론트엔드 개발 서버 주소(예: `localhost:5173/api/users`)로 요청을 보내면, Vite 개발 서버가 이를 받아 뒷단의 백엔드 서버(예: `localhost:8000/users`)로 요청을 대리 전달한다.
- **존재 이유:** 브라우저의 보안 정책인 **CORS(Cross-Origin Resource Sharing) 제한을 개발 단계에서 손쉽게 우회**하기 위한 리버스 프록시 꼼수이다.

### 🏗️ 실제 프로덕션 환경의 인프라 흐름
리버스 프록시를 적용한다고 해서 프로그램이 무한정 늘어나는 것은 아니다. **Nginx 제품 자체가 리버스 프록시 서버의 역할**을 완벽히 수행하므로 구조는 다음과 같이 명료해진다.

```
[Client] <──> [Nginx (Reverse Proxy 역할)] <──> [Uvicorn (WAS)] <──> [MySQL]
```

- 클라이언트는 Nginx의 IP만 알 수 있으며, 뒷단의 Uvicorn과 MySQL의 실제 주소 및 포트는 완벽하게 숨겨진다. 
- Uvicorn(WAS)은 자체적으로 프록시 기능을 수행하지 않으며, 고속 ASGI 처리에 집중하고, 앞단의 리버스 프록시(Nginx)가 전달해 주는 정제된 요청만 받아 비즈니스 로직을 구동한다. 
## 그렇다면 Axios도 프록시인가? 

아니다. Axios는 프록시가 아닌 **HTTP 클라이언트 라이브러리**다. 

- **Axios:** 요청을 최초로 생성하고 발송하는 **도구(코드/라이브러리)**이다. 
- **프록시:** 발송된 요청을 중간에서 가로채서 전달해 주는 **물리적인 서버 프로그램**이다. 
## 프로젝트에서는 어디에서 사용하는가? 
- **프론트엔드:** React+Vite 환경에서 백엔드(FastAPI)와의 CORS 문제를 해결하기 위해 Vite 개발 서버 내장 **리버스 프록시(`server.proxy`)** 기능을 활용하고 있다. 
- **백엔드:** 로컬 개발 단계이므로 별도의 인프라용 리버스 프록시(Nginx)는 구성하지 않았다. 
- 배포 단계에서 Nginx를 리버스 프록시로 전면에 배치할 예정이다.
