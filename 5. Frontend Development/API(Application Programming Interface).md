## 왜 필요할까?

- **캡슐화 및 보안성 확보:** 파이썬으로 작성된 코드가 자바로 빌드된 시스템 내부의 메모리 데이터나 핵심 소스코드를 직접 들여다보거나 임의로 수정하는 행위는 시스템 보안 및 무결성 측면에서 극도로 위험하다. API는 내부 구현을 은닉(Encapsulation)한 채, 허용된 안전한 관문으로만 데이터를 주고받도록 통제한다.
- **자원 및 개발 효율성 극대화:** 타사 시스템의 방대한 데이터(예: 지도 정보, 날씨 데이터 등)를 내 서비스 데이터베이스에 모두 직접 구축하는 것은 불가능에 가깝다. API 인터페이스를 통하면 상대 서버가 정제해 둔 필요한 가공 데이터만 실시간으로 원격 호출하여 유연하게 레버리지할 수 있다.

## 정의

- **API (Application Programming Interface)**는 하나의 소프트웨어 컴포넌트가 **다른 소프트웨어 컴포넌트의 기능, 데이터, 혹은 운영체제의 자원을 호출하여 상호작용할 수 있도록 설계된 추상화된 규칙과 인터페이스 집합**이다.
- 운영체제 수준의 시스템 API, 라이브러리 함수 API 등 광범위한 영역에 존재하며, 특히 네트워크 환경에서 서로 다른 기기 간에 통신 규약(**HTTP 프로토콜**)과 정제된 데이터 포맷(**JSON, XML 등**)을 매핑하여 연동하는 아키텍처 스타일을 **웹 API (Web API)**라고 부른다.

## 웹 API (Web API)의 일반적인 비즈니스 생명주기

```
[클라이언트의 요청] ➔ [네트워크 프로토콜 통신] ➔ [서버측 인가(Authorization) 검증]  
															│  
															▼  
[클라이언트에게 결과 전송] <─ [HTTP 상태 코드 응답] <─ [비즈니스 도메인 로직 처리]
```

## 웹 API 핵심 아키텍처 컴포넌트 
### 1. HTTP 메서드 (Method)의 동작 사양 명세 
- **`GET` (조회):** 특정 자원을 안전하게 가져오는 메서드로, 서버 상태를 변경하지 않는 안전한(Safe) 성격을 가진다. 
- **`POST` (생성):** 서버에 새로운 하위 자원을 등록하거나 특정 행위를 실행할 때 사용한다. 
- **`PUT` (전체 대체):** 지정한 식별자 위치의 리소스 **전체를 클라이언트가 보낸 데이터로 '통째로 덮어쓰기(Replace)'**한다. (동일 요청을 여러 번 날려도 결과가 같은 **멱등성**을 지닌다.) 
- **`PATCH` (부분 수정):** 리소스의 전체가 아닌, **특정 일부 필드나 속성만 '부분적으로 변경(Partial Update)'**할 때 사용한다. 
### 2. HTTP 상태 코드 (Status Code)의 명확한 분류 
- **`2xx` (성공):** 클라이언트가 보낸 HTTP 요청을 서버가 문법적으로 완벽히 이해하고 **정상적으로 접수 및 처리 완료**했음을 뜻한다. (예: `200 OK`, `201 Created`) 
- **`4xx` (클라이언트 오류 / 실패):** **클라이언트의 잘못된 요청으로 인해 서버가 정상적인 처리를 수행하지 못하고 거부**했음을 뜻한다. 
- `401 Unauthorized`: 요청자가 누구인지 증명하는 **인증(Authentication)** 과정(예: 로그인)이 유실되었거나 실패했을 때 반환된다. 
- `403 Forbidden`: 인증은 되었으나, 해당 사용자가 해당 자원이나 특정 API 엔드포인트에 접근할 수 있는 **인가(Authorization)** 권한이 없을 때 반환된다. 
- `404 Not Found`: 요청한 API의 URI 경로(주소)가 서버에 존재하지 않을 때 반환된다. 
- **`5xx` (서버 오류):** 클라이언트의 요청은 올바르나, **서버 자체의 코드 버그, 예외 처리 미흡, 혹은 인프라 장애(DB 다운 등)**로 인해 최종 처리가 실패했음을 뜻한다. (예: `500 Internal Server Error`) 
### 3. JSON 데이터 형식
- 웹 인프라 환경에서 언어 중립적으로 데이터를 구조화하여 송수신할 수 있는 텍스트 포맷이다. (※ 데이터 내 주석 추가는 RFC 표준 명세상 금지된다.) 
```
json { "userName": "홍길동", "age": 25, "skills": ["Python", "JavaScript"] } 
```
### 4. API 보안: 인증(Authentication) vs 인가(Authorization) 
- **인증 (Authentication):** "이 요청을 보낸 주체가 진짜 신뢰할 수 있는 사용자 본인이 맞는가?"를 검증하는 과정 (예: 아이디/비밀번호 매칭) 
- **인가 (Authorization):** "인증이 완료된 주체가, 요청한 특정 API 자원에 접근할 수 있는 자격 증명(Permission)을 올바르게 소지했는가?"를 검증하는 과정 (예: HTTP 헤더에 유효한 **API Key**나 **JWT 토큰**을 첨부하여 권한을 증명하는 행위) 
## 프로젝트에서는 어디에서 사용하는가? 
- **도메인 간 통신 결합 구조:** 프론트엔드 컴포넌트(React)와 백엔드 비즈니스 로직(FastAPI) 사이의 데이터 상호작용 채널로 **RESTful 웹 API** 아키텍처를 전면 채택하여 운영 중이다. 
- **예외 매핑 표준화:** 백엔드 레포지토리 및 서비스 계층에서 오류가 발생했을 때 이를 가두어 두고, 상위 라우터 단에서 적절한 `4xx` 혹은 `5xx` 표준 HTTP 상태 코드와 사내 규격화된 에러 JSON 패킷으로 가공하여 클라이언트에게 안전하게 반환하는 인프라 파이프라인을 유지하고 있다.
