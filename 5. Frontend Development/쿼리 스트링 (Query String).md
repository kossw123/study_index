## 왜 필요할까?

- **식별 대상의 세부 제어 (정렬/필터):** 특정 비즈니스 자원(Resource)의 전체 목록 중, 사용자가 원하는 기준에 부합하는 데이터만 정밀하게 필터링하거나 정렬하여 서빙할 수 있다.
  - 정렬 방식 지정: `sort=latest`
  - 노출 개수 제한: `limit=10`
  - 카테고리 필터링: `category=shoes`
- **상태의 유지와 손쉬운 공유 (Shareable URL):** 현재 사용자가 보고 있는 화면의 조건(필터 정보, 정렬 방식, 현재 페이징 번호)이 URL 주소창에 고스란히 텍스트로 남는다. 이 덕분에 유저가 해당 주소를 그대로 복사해 타인에게 공유하거나 북마크하더라도, 전 세계 어디서나 완벽하게 동일한 조건의 가공 화면을 즉시 동기화해 볼 수 있다.

## 정의

- **쿼리 스트링 (Query String)**은 클라이언트가 서버로 제어 정보를 전달하기 위해, **URL 주소의 끝에 물음표(`?`)를 붙이고 그 뒤에 `Key=Value` 형태로 데이터 쌍을 명시하는 통신 포맷**이다.
- 두 개 이상의 매개변수를 결합하여 전송할 때는 **`&` (앰퍼샌드)** 기호로 연결하여 확장한다.
- 데이터 조회(`GET`)의 상세 조건 지정에 주로 활용되지만, 기술적으로는 데이터 생성(`POST`)이나 수정(`PUT`), 삭제(`DELETE`) 등 **모든 HTTP 메서드 문맥과 결합하여 부가 옵션을 전달하는 용도로 제약 없이 사용 가능**하다.

## 동작 과정 및 대안 기술과의 아키텍처적 비교

### 1. 기본 구문 표준 구조
```text
https://domain.com
```

### 2. 조건별 데이터 전달을 위한 백엔드 라우팅 기법 대조
> ⚠️ **[교정] 쿼리 스트링이 없다고 해서 수만 개의 고정 페이지를 미리 만들 필요는 없다.** 백엔드 아키텍처는 목적에 따라 아래와 같이 유연한 대안 기술을 분기하여 사용한다.

- **방법 A: 패스 파라미터 (Path Parameter / 동적 라우팅)**
  - 자원의 계층 구조나 고유 식별자를 상위 주소의 한 축으로 묶어낼 때 주로 사용한다.
  - *예시: `/v1/shoes/nike/270` ➔ 백엔드 라우팅 엔진이 특정 자원의 식별 경로(`/{brand}/{size}`)를 동적으로 파싱하여 연산하므로 주소를 미리 다 파둘 필요가 없다.*
- **방법 B: 쿼리 스트링 (Query String)**
  - 자원의 구조는 그대로 두고, 정렬이나 다중 조건 필터, 검색어 전송 등 **자원의 상태를 정제하는 옵션**을 유연하게 던질 때 최적화되어 작동한다.
  - *예시: `/v1/shoes?brand=nike&size=270&sort=low-price`*
- **방법 C: 요청 본문 (Request Body)**
  - 보안상 URL 주소창에 검색 조건이나 필터 데이터가 노출되면 안 되거나, 구조가 극도로 복잡한 다차원 필터링을 수행할 때는 `POST` 메서드를 열고 HTTP 바디에 데이터를 실어 나른다.

> 💡 **[성능 주의] 쿼리 스트링과 서버 부하의 진실**
> 디자인을 유지한 채 데이터만 가볍게 갈아 끼워 화면을 부분 갱신(서버 부하 감소)하는 것은 브라우저의 AJAX 통신이나 클라이언트 사이드 렌더링(CSR) 프레임워크가 전담하는 영역이다. 쿼리 스트링 자체는 문자열 규격일 뿐이며, 오히려 인덱스가 설계되지 않은 무분별한 다중 복합 쿼리 스트링이 서버에 인입되면 **DB 풀 스캔을 유발하여 백엔드 인프라에 극심한 과부하를 주는 주원인**이 되므로 정밀한 인덱싱 설계가 수반되어야 한다.

## 프로젝트에서는 어디에서 사용하는가?

- **대규모 카탈로그 조회 및 페이징:** 상품 목록 페이지나 주문 내역 대시보드를 조회하는 엔드포인트에서 페이지 번호(`page=2`), 페이지당 노출 개수(`size=20`), 다중 필터(`status=SHIPPED`) 조건을 전송받는 관문 아키텍처로 사용 중이다.
- **FastAPI 의존성 주입 연동:** 백엔드(FastAPI) 라우터 계층에서 `Query()` 컴포넌트를 주입받아, 유입되는 쿼리 스트링 매개변수의 최솟값/최댓값 유효성 검증 및 기본값(Default Value) 설정을 자동화하는 방식으로 프로젝트를 구조화하였다.
