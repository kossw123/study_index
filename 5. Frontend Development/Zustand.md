## 왜 필요할까?

- **컴포넌트 스코프의 결합도 해소:** React의 단방향 데이터 흐름 특성상, 멀리 떨어진 컴포넌트 간 상태를 공유하려면 부모를 거쳐 깊숙이 내려주어야 하는 **Prop Drilling** 현상이 필연적으로 발생한다. 이 과정에서 데이터를 단순 전달만 하는 중간 컴포넌트들이 불필요한 가독성 저하를 겪게 된다.
- **유연한 외부 상태 관리 스토어 구축:** 비즈니스 상태 공간을 React 컴포넌트 트리 외부의 안전한 클로저 영역으로 격리(Store)하여, 컴포넌트 간 깊이에 종속되지 않고 필요한 컴포넌트만 해당 지표를 정밀 구독(Subscribe)할 수 있도록 구조화하기 위함이다.

## 정의

- **`Zustand` (주스탠드)**는 독일어로 '상태'라는 뜻을 가지며, **파이썬/자바스크립트 등 다양한 웹 환경에서 클로저(Closure) 기반으로 가볍고 직관적인 글로벌 상태 저장소(Store)를 생성할 수 있게 돕는 모던 상태 관리 라이브러리**이다.
- React의 Context API나 무거운 Provider 배치 없이 훅(Hooks) 인터페이스만으로 전역 상태에 직접 접근할 수 있다.

```
                    [ Zustand 전역 외부 Store ]  
             ┌──────────────────┼──────────────────┐  
             ▼                  ▼                  ▼  
        [user 상태]         [cart 상태]        [count 상태]  
             ↑                  ↑                  ↑  
       (정밀 Selector)    (정밀 Selector)    (정밀 Selector)  
             │                  │                  │  
       [Header 컴포넌트]    [Cart 컴포넌트]    [Counter 컴포넌트]
```

## ⚠️ [교정] 리렌더링(Re-rendering) 조건 및 요약 안내

- 리렌더링 방지 및 Redux Toolkit과 Zustand의 비교, `useShallow` 활용 예시 등 상세한 코드와 가이드라인은 referenced web documents에서 전체 내용을 확인할 수 있습니다.
- 보안과 서버 상태 분리 전략에 대한 추가적인 모범 사례 또한 referenced web documents에 상세히 정리되어 있습니다.
