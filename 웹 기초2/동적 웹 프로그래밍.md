## 왜 필요한가?

- 시대가 발전함에 따라 정적인 데이터로 원하는 정보를 얻기 위해 데이터의 양과, 그에 따른 연산량 부족으로 인해 탄생했다.

## 정의

사용자의 요청에 따라 페이지가 변화하며 실시간 데이터에 맞춰 서버가 웹 페이지를 실시간으로 만들어 제공하는 방법이다.

정적 웹 프로그래밍과 같이 클라이언트와 서버가 존재하며, www 서비스를 통해 통신해 원하는 데이터를 요청하고 전송한다.


## 동작 과정


클라인트 <-> 웹 서버 <-> 웹 애플리케이션 서버 <-> 데이터베이스

# 오해하지 말아야 할 것

정적 웹 프로그래밍에서 WAS와 DB가 추가되었고, 물리적으로 컴퓨터가 2대가 필요하다고 생각했지만, 그건 사실이 아니다.

서버란 컴퓨터를 칭하는게 맞지만, 더 정확하게 말하자면 사용자에게 원하는 데이터를 주는 프로그램이다.

	“즉, WAS는 컴퓨터가 2대가 필요하진 않고 하나의 컴퓨터에서 나눠 쓸 수 있다.“

요즘은 하드웨어의 발달로 정적, 동적 컨텐츠를 같이 처리할 만큼 성능이 올라오기도 했고, 배포를 할 때 웹 서버와 WAS를 나눈다면 배포와 관리에 대한 어려움이 있기 때문에 이를 합친 FastAPI나 SpringBoot 같은 프레임워크가 많이 생겼다.

# 현대의 동적 웹 프로그래밍 구조

대규모 서비스나 엔터프라이즈 환경에서는 이 두 서버를 굳이 합치지 않는다.
앞단에는 웹 서버(Apache, Nginx등)을 놓고 뒷단에는 결합형 WAS를 배치하는 구조를 사용한다.

Nginx같은 경우 앞 단에 두면 로드밸런싱(Load Balancing)과 보안(Reverse Proxy)같은 강력한 기능을 사용할 수 있다.

## 프로젝트에서는 어디에서 사용하는가?

- 필요한 이유에서 서술한 바에 따라, 전체 구조를 동적 웹 프로그래밍으로 작성
